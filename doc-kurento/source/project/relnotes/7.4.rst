======================================
Kurento 7.4 Release Notes (UNRELEASED)
======================================

This page collects the changes that are being added to the next release.

Kurento 7.4.0 has not been released yet.

See https://doc-kurento.readthedocs.io/en/latest/project/relnotes/7.4.html for the latest version of this document.

To install Kurento Media Server: :doc:`/user/installation`.

.. contents:: Table of Contents



Added
=====

* **H.265 recording in MP4 and MKV**. The RecorderEndpoint has a new optional constructor parameter, *videoCodec*, to choose the video codec that is stored in the recording file independently of the container.



Choosing the recording video codec
----------------------------------

The new enum ``RecorderVideoCodec`` has the values ``H264``, ``H265``, ``VP8``, ``VP9`` and ``AV1``. When it is not provided, the behavior is the same as before (H.264 for MP4 and MKV, VP8 for WEBM). Invalid combinations of container and codec are rejected when creating the RecorderEndpoint, with a ``MEDIA_OBJECT_ILLEGAL_PARAM_ERROR`` error.

If the incoming video already uses the requested codec, it is stored as-is, without any transcoding. H.265 is written as ``hvc1``, which can be played by Safari and QuickTime.

.. code-block:: java

   RecorderEndpoint recorder = new RecorderEndpoint
       .Builder(pipeline, "file:///var/lib/kurento/recording.mp4")
       .withMediaProfile(MediaProfileSpecType.MP4)
       .withVideoCodec(RecorderVideoCodec.H265)
       .build();

.. code-block:: js

   const recorder = await pipeline.create("RecorderEndpoint", {
     uri: "file:///var/lib/kurento/recording.mp4",
     mediaProfile: "MP4",
     videoCodec: "H265",
   });

.. note::

   Servers older than 7.4.0 silently ignore the *videoCodec* parameter. See :doc:`/knowledge/recording-codecs` for the valid combinations, the cases that need transcoding, and the minimum versions.



Fixed
=====

* Transcoding to H.265 (for example, when recording H.265 from a source that sends another codec) now works: the encoder is selected regardless of the stream format, and its output is parsed before being muxed or payloaded.
